# Less is more

Adapted from Jakub Krehel’s [Less is more, more or less](https://jakub.kr/writing/less-is-more).

Understand the person, task, and context before adding interface elements. Preserve the user’s requested features, visual style, and scope.

- Give each control, section, animation, and dependency a concrete purpose. Remove additions that do not improve the task.
- Keep the main path obvious. Reuse familiar patterns and existing components.
- Write friendly, concise copy. Include what people need to act; remove repetition and implementation details.
- For flows, check what the site knows and what the person knows at each step. Keep this reasoning and test controls out of the client-facing interface.
- Use motion to explain changes or provide feedback. Frequent actions should feel immediate.
- Choose the smallest readable implementation that supports the required behavior.
- Review the rendered interface and click through representative paths. Check that copy and behavior agree. State verification limits before calling work ready to share.
- No eyebrows or gratuitous, wordy copy

Scale the review to the change. Keep useful detail, accessibility, and necessary recovery paths.
